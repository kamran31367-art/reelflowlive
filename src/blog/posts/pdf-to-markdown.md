The [PDF to Markdown Converter](/pdf-to-markdown/) extracts text from a PDF's existing text layer and writes it into Markdown. It runs locally with PDF.js and adds a page heading before each page's extracted lines.

This distinction matters: extraction is not optical character recognition. If the PDF contains real text objects, the tool can read them. If a page is only a scan, there are no characters to extract, and the tool does not guess them from the picture.

## When PDF text extraction is useful

Use the converter when you have a digital report, exported document, article or other PDF with selectable text and you need a plain-text starting point. The output is convenient for search, editing, note-taking or restructuring in Markdown.

It is less reliable for visual documents. Magazines, slide decks, forms, multi-column papers and complex tables often depend on placement rather than a simple top-to-bottom flow. Extracted text can be complete but poorly ordered.

## File control and action button

The **PDF file** dropzone accepts one `.pdf` file or a file identified as `application/pdf`. Click it to choose a document or drag a PDF onto it. Multiple files are not supported.

Press **Extract Markdown** to start. The converter opens the PDF, reads each page's text content and builds one Markdown string. There is no automatic conversion when a file is selected, and there is no page-range field.

The **Markdown text** pane shows the result. **Copy** copies it, and **Download** saves `pdf-to-markdown.md` as UTF-8 text. **Reset** clears the selected PDF and the output.

## A worked two-page example

Suppose a digital PDF has two pages. Page one contains a title and two lines; page two contains another heading and one line. After extraction, the Markdown begins like this:

```markdown
## Page 1

Project notes
Prepared by the editorial team.
Review date: 27 November 2026.

## Page 2

Open questions
Confirm the final image list.
```

The `## Page 1` and `## Page 2` lines are generated by the converter. **Project notes** and **Open questions** are ordinary extracted text; they are not promoted to Markdown headings based on their font size.

## How lines are assembled

PDF.js returns text items with position data. The converter takes each item's vertical coordinate, rounds it into a small positional bucket and groups fragments that share a bucket. Groups are sorted from higher positions to lower positions, which approximates reading from the top of the page downward.

Fragments on the same grouped line are joined with spaces. Separate lines are joined with line breaks, and the page's text is placed under `## Page N`.

Text may also retain original line breaks, repeated headers, page numbers and hyphenation. Blank lines in the PDF do not necessarily map to reliable Markdown paragraphs, so the output can look denser than the visual page.

## Why scanned pages produce little or no text

A scan is a picture of text. The PDF may display the picture perfectly while containing no text objects beneath it. PDF.js text extraction reads the text layer, not the pixels, so the converter has nothing to return for that page.

The result can still contain the generated heading:

```markdown
## Page 4
```

OCR is the separate process of recognising characters in an image. This tool does not include OCR, does not call an OCR service and does not improve scan accuracy. If the words must become text, run an appropriate OCR workflow first and check its recognition against the page.

## Structure that is not reconstructed

The converter does not inspect font size or style to infer headings. It does not preserve Word-style paragraph roles, list numbering, table cells or hyperlink destinations. A link may lose its target even when its visible label is extracted.

For academic or technical PDFs, equations and specialised symbols may be extracted inconsistently because their appearance depends on fonts and PDF encoding. Verify important symbols, units, references and numerical values against the original.

The code declares no fixed PDF byte-size cap or page-count maximum. Every page is processed sequentially, so large or image-heavy files can make the tab slow or unresponsive. Password-protected or damaged PDFs may fail because there is no password or repair control. Split long documents when possible, and work from an unlocked, valid copy.

## Common mistakes to avoid

Do not expect source headings to arrive with correct Markdown levels. Add those levels yourself after checking the document hierarchy. Do not assume extracted line breaks represent paragraphs; reflow the text where the meaning requires it.

Avoid publishing a multi-column extraction without comparing reading order. A technically complete transcript can still be unusable if every line combines two unrelated columns.

Do not interpret an empty page section as an empty original page. Check whether the page is a scan. Also do not use the generated page headings as evidence of the source's semantic structure; they are navigation labels added by the converter.

Finally, verify tables, equations, names, dates and figures. Text extraction can preserve characters while still losing the relationships that made them understandable on the page.

## Local processing and privacy

The PDF is read in the browser, parsed by PDF.js and converted into a text string in the open tab. No PDF upload or account is required. The worker code used for parsing is served with the site.

This makes the tool suitable for confidential reports, internal records and unpublished documents. The file is not sent to a remote extraction service, and the Markdown remains local until you copy or download it.

Local processing does not make the open page or the downloaded text automatically safe. Use normal device access controls, avoid leaving sensitive results visible on a shared screen and remember that copied text may contain information from every page of the PDF.

## A practical workflow

1. Confirm that the PDF contains selectable text rather than only scanned images.
2. Keep the original PDF open for comparison.
3. Split the document first if you need only a small section.
4. Choose the PDF and press **Extract Markdown**.
5. Check that each expected page has body text.
6. Review reading order, especially on columns, tables and diagrams.
7. Add real heading levels and paragraph breaks in a text editor.
8. Verify important values and symbols against the PDF.
9. Download `pdf-to-markdown.md`, rename it and retain the source.

For a scan, stop after the text check and use a separate OCR process. Converting the resulting recognised text into Markdown is a different step from reading an existing text layer.

## Final checklist

- The PDF is valid and accessible without an unknown password.
- The required pages contain a real text layer.
- Every expected page has been inspected in the output.
- Multi-column and table reading order has been checked.
- Source headings have been assigned correct Markdown levels.
- Images, equations and links have been handled manually where needed.
- Important values match the original PDF.
- The Markdown is saved and the PDF is retained.

PDF-to-Markdown conversion is a fast way to obtain editable text from a digital PDF. Its reliability comes from the source text layer and the simplicity of the layout, not from any ability to recognise a scanned page.
